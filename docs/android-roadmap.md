# ClawChat Android 路线图（v2.15.0 基线）

**状态：** 现行版本路线。本文件只规划 **Android 手机**；不涉及 iOS、Web、桌面。
**基线：** v2.15.0（`flutter_app/pubspec.yaml` 的 `2.15.0+N`；交付提交 `bbe0d33`）。
**与其它文档的关系：**

- 产品边界以 [`PRODUCT.md`](../PRODUCT.md) 为准（口袋个人 Agent 机器；Linux 是通用手，Android 是私有感官与执行器，聊天是遥控器）。
- [`2026-09-15 迭代计划`](plans/2026-09-15-pocket-agent-machine-iteration-plan.md) 是 I0–I7 的历史迭代计划；本文件从 **v2.16** 起给出可执行的版本节奏与验收标准。
- 冲突时：非目标以 `PRODUCT.md` 为准；版本范围与验收以本文件为准，并在实现 PR 中记录差异。

**维护规则：** 每个版本一个章节。发布后把 `CHANGELOG.md` 的章节名补到对应标题；未完成项移到下一版本并从原版本移到「遗留」，不删除。

## 1. 产品定位与 Android-only 非目标

### 1.1 一句话定位

ClawChat 是跑在 Android 手机上的**口袋个人 Agent 机器**：通用工作在嵌入式 Alpine（proot）里完成，手机隐私数据与手机动作只走 Android API，聊天负责驱动两边并征求同意。

### 1.2 三条边界（所有新功能都要过这个过滤器）

| 层 | 职责 | 例子 |
| --- | --- | --- |
| Linux / proot | 通用手：工作区、脚本、包、技能、网页抓取 | bash、workspace 文件、`web_fetch` |
| Android API | 私有感官与执行器 | 日历 / 短信 / 联系人读取、闹钟、分享、拨号、外发短信 |
| Chat | 遥控器：展示进度、审批、恢复 | 会话、工具卡片、审批对话框、任务中心 |

### 1.3 明确非目标（本路线不做）

- **不做 iOS / Web / 桌面**：不新增对应平台目录、不为其改架构、不做跨平台抽象。
- **不做常驻系统助手**：不做开机启动模型、通知监听、无障碍接管、静默外发。
- **不做云 Agent**：本地状态是权威；没有强制账号、没有托管控制面、没有 ClawChat 自营遥测。
- **不做端侧大模型**：不下载、不内置、不运行本地大模型，也不做端侧推理。ClawChat 是**云端模型客户端**，设备侧只负责安全工具运行、权限控制与网络韧性。
- **不做移动 IDE**：没有 LSP、仓库索引、代码补全、IDE 外壳。
- **不做 Play Store 专项改造**：以侧载 APK 为主要分发；需要时再单独决策。
- **不做自动执行**：任何工具、技能、MCP、后台任务都不能绕过 `ToolPolicy` / 技能同意 / 每次操作审批。

### 1.4 权威不可回退项

以下语义在所有版本中保持冻结，任何版本都不得为了新功能而放宽：

1. 外发（`phone_send`）默认关闭，读取权限永不隐含发送权限。
2. 不可信来源（短信 / 日历 / 联系人 / 网页 / MCP）不得直接驱动外发、跳转或网络目的地；taint 规则只收紧不放宽。
3. 后台只服务用户刚启动的那次 run；进程死亡后**不自动重跑**。
4. 通知锁屏保持隐私（无会话标题、无正文、无工具参数）。
5. 凭据只进加密存储，绝不进入备份、日志、诊断导出或明文偏好。
6. 模型请求只发往用户配置的 Provider；ClawChat 不做自建中转，也不把提示词缓存到自有服务。

## 4. v2.17 — Agent run journal、取消、恢复、前台生命周期

**目标：** 让「这次 run 到底发生了什么」始终可查、可取消、可解释；把 run 从 `ChatProvider` 里拆出来，形成独立状态机。

### 4.1 工作项

| 编号 | 工作项 | 具体内容 | 验收方式 |
| --- | --- | --- | --- |
| RUN-1 | Run journal | 持久化 run 记录：`runAttemptId`、会话、起止时间、每次工具尝试（operationId、策略判定、receipt、结果状态）；仅本地加密存储，可清理 | 强杀后重启能看到完整 run 轨迹；轨迹不含工具参数中的敏感值 |
| RUN-2 | 取消语义 | 单会话取消、通知 Stop、取消后不再派发新工具；已发出的工具结果标记 `cancelled`；部分文本保留 | 三种入口分别取消；取消后无新工具调用、无外发 |
| RUN-3 | 恢复策略 | 崩溃 / 强杀 / 重启后不自动重跑；未知结果只提供查看与弃置；显式「继续」才产生新 `operationId` | 四类场景矩阵；`unknown_outcome` 与原 receipt 语义不变 |
| RUN-4 | 前台生命周期 | 前台服务只服务当前 run，结束即停；通知为粗粒度状态 + Stop；App 退到后台不启动新 run；`RECEIVE_BOOT_COMPLETED` 不启动 agent | Kotlin 生命周期单测 + 真机：切后台、锁屏、来电、低内存回收 |
| RUN-5 | Run 状态机拆分 | Session / Run / ToolAttempt / Machine 四个对象各自持有状态；`ChatProvider` 只做门面映射 | `chat_provider.dart` 不再新增策略代码；现有聊天 / 取消 / 多会话测试全过 |

### 4.2 本版不做

- 不做常驻守护进程、不做 WorkManager 定时跑模型、不做后台自动重试。
- 不做通知监听、无障碍、开机自启。
- 不做多设备同步或云端 run 记录。

### 4.3 依赖

- v2.16 的恢复与中断可见性基线。
- 既有 receipt / `unknown_outcome` / 审批语义不变，只做展示与生命周期收口。

### 4.4 退出条件

- 强杀、崩溃、取消、重启四类场景的真机矩阵通过。
- run journal 可导出供排查，导出内容不含凭据与工具原始参数。
- 取消与重启后不产生任何未确认的外发或网络请求。

**目标：** 把 Android 系统集成从「各功能各自为战」收成一个可复用的 broker，并收口 2.14 遗留的真机验证。

### 5.1 工作项

| 编号 | 工作项 | 具体内容 | 验收方式 |
| --- | --- | --- | --- |
| AND-1 | 分享入站 | `ACTION_SEND` / `ACTION_SEND_MULTIPLE` 全路径：文本、图片、多文件；来源不可读时 fail-closed 并给出明确提示；缓存配额与去重不变 | 从浏览器、相册、微信 / 文件管理器各分享一次；超限与不可读来源有提示 |
| AND-2 | 分享出站 | 导出对话 / 文件到系统分享；内容上限（文本 64 KB、主题 1 KB、URI 64 个）与去重语义保持 | 大文本与多图分享不崩溃、不截断关键内容 |
| AND-3 | 文件与 SAF | 系统文件选择器导入 / 导出、多目标备份真机验证；工作区范围规则不放宽 | SAF 真机验证收口（2.14 遗留项）；权限拒绝路径有明确提示 |
| AND-4 | 通知 | 渠道分类、锁屏隐私、通知动作（Stop / 打开会话）、免打扰与空通知处理 | 真机通知矩阵：锁屏、免打扰、多会话并行、权限关闭 |
| AND-5 | 权限 broker | 统一请求 / 拒绝 / 永久拒绝 / 撤销后的引导；覆盖日历、短信、联系人、通知、存储；请求与当前 run 绑定并解释用途 | 权限矩阵真机测试（同意 / 拒绝 / 永久拒绝 / 系统设置撤销） |
| AND-6 | 存储与清理 | 缓存、分享缓存、staging 目录的配额与清理；低存储时给出可执行提示 | 磁盘接近满时导入 / 备份 / 分享都不静默失败 |

### 5.2 本版不做

- 不申请与功能无关的权限；`MANAGE_EXTERNAL_STORAGE` 仅用于用户发起的流程，永不作为 agent bash 的绑定。
- 不做通知监听、无障碍、悬浮窗默认开启（仍保持 Developer Mode + 显式开关）。
- 不做 Play 专属 API 与 Play 审核专项。

### 5.3 依赖

- v2.16 的导航 / 恢复基线；v2.17 的 run 绑定（权限请求要能解释属于哪次 run）。

### 5.4 退出条件

- 权限矩阵与 SAF 真机验证通过；2.14 遗留的 SAF、MCP stdio 真机 smoke 明确收口或转为下一版阻塞项。
- 分享 / 文件 / 通知三类的失败路径都有用户可读提示，且不静默丢数据。

## 6. v2.19 — 云端 Provider 与网络韧性

**目标：** 让 ClawChat 在真实移动网络下可靠：Provider 可配置可切换、流式响应断开可恢复、超时与错误可解释、弱网与切网不丢会话状态。设备侧不做任何端侧推理（见 §1.3）。

### 6.1 工作项

| 编号 | 工作项 | 具体内容 | 验收方式 |
| --- | --- | --- | --- |
| NET-1 | Provider 配置与切换 | API 格式 / base URL / 模型 / 采样参数支持全局与会话两级；模型组只解析凭据可用的成员；会话内切换 Provider 时保留上下文与工具状态，缺凭据时明确报错而不是静默回退 | 配置三家 Provider 并逐一切换；缺 key 时提示明确；切换后历史消息与工具调用可继续 |
| NET-2 | 流式断线恢复 | 流式响应中断（网络闪断、切网、前台服务被回收）保留已生成文本并标记中断；重试语义明确（重新请求或续写），不重复计费式重发、不重复工具调用；用户取消过的 run 不自动重跑 | 飞行模式切换、隧道 / 弱网、Wi-Fi 与蜂窝互切三类场景；中断后文本保留、重试行为可预期 |
| NET-3 | 请求 / 响应超时 | 连接、首 token、总时长、工具调用分别有超时；超时可取消、可重试；取消立即释放连接并结束前台服务 | 慢速 Provider 与弱网下超时行为一致；取消后无残留连接与通知 |
| NET-4 | 网络变化 | 监听网络可用性与计费网络变化：弱网提示、蜂窝下的大内容传输前提示、离线时明确拒绝并保留草稿 | 切网、离线、热点、VPN 场景；离线发消息要求明确失败而不是无限转圈 |
| NET-5 | 错误可解释性 | HTTP / 网络 / 流式协议错误归入统一分类与用户可读文案（含重试建议）；保留脱敏诊断；UI 不展示原始响应体 | 401 / 403 / 429 / 5xx、超时、TLS、DNS 各有文案；诊断导出无凭据 |
| NET-6 | 有限本地缓存 | 只缓存可安全缓存的内容（会话、模型列表、用量摘要、草稿）；缓存有配额与清理入口；凭据只进加密存储 | 离线可读历史会话与草稿；缓存中无明文凭据；超配额可清理 |
| NET-7 | 凭据与地址安全 | 密钥只存加密存储；自定义 base URL 校验（HTTPS、不得内嵌凭据）；代理与白名单配置明确提示风险 | 明文偏好与备份中无密钥；非法 URL 被拒绝并给出原因 |

### 6.2 本版不做

- 不做端侧大模型：不下载、不内置、不运行本地模型，不做端侧推理（与 §1.3 一致）。
- 不做 ClawChat 托管推理或自建中转；请求只发往用户配置的 Provider。
- 不做后台自动重试或自动续跑；重试只发生在用户可见的前台 run 中。
- 不做多设备同步、云端会话存储或运营商级别的网络优化。

### 6.3 依赖

- v2.17 的 run 生命周期与取消语义（断线恢复、超时与取消必须绑定 run）。
- v2.18 的通知与权限 broker（弱网提示、前台服务收尾与网络状态读取）。

### 6.4 退出条件

- 弱网、切网、离线三类场景下：会话状态不丢、错误可解释、重试行为可预期。
- 至少一台真机完成弱网矩阵；Provider 切换与缺凭据路径都有明确提示。
- 凭据与诊断导出通过隐私回归（无明文密钥）。

## 7. v2.20 — Skill / MCP 生态与信任更新

**目标：** 让技能与 MCP 可维护地演进：能更新、能回滚、能解释权限变化；不把信任模型换成「安装即信任」。

### 7.1 工作项

| 编号 | 工作项 | 具体内容 | 验收方式 |
| --- | --- | --- | --- |
| ECO-1 | 技能版本与回滚 | 多版本历史（不止上一份包）、版本比较、回滚入口与禁用默认值 | 安装 → 升级 → 回滚端到端；回滚后保持禁用 |
| ECO-2 | 信任更新 | 能力差异同意（新增权限必须重新同意）、摘要 / 签名校验升级；清单仍为唯一能力来源 | 权限变宽的包必须重新同意；摘要不符直接判无效 |
| ECO-3 | 模板生态 | 本地模板包格式、应用内导入、只读预览；不引入远程执行 | 导入一个模板包 → 预览 → 安装 → 同意 → 使用 |
| ECO-4 | MCP 生态 | 多服务器配置校验、健康状态、run-scoped 生命周期、结果统一为不可信来源；密钥只从用户配置读取 | 多服务器并行一次 run；单服务器崩溃不影响其他；结果不触发外发 |
| ECO-5 | 清理与审计 | 技能 / MCP 的停用、卸载、残留清理；本地审计记录不含敏感参数 | 卸载后无残留可执行入口；审计导出可读且无凭据 |

### 7.2 本版不做

- 不做应用内 OAuth、不做远程市场托管的任意代码执行。
- 不做常驻 MCP supervisor、不做后台自动更新技能。
- 不把手机日历 / 短信能力搬进技能或 MCP（继续走 Android API）。

### 7.3 依赖

- v2.18 的权限 broker；v2.19 的网络与超时 / Provider 基线（技能与 MCP 的云端调用复用同一套超时与错误语义）。

### 7.4 退出条件

- 信任更新端到端测试通过：安装 → 升级 → 权限变化 → 重新同意 → 回滚。
- MCP 真机 smoke：启动、列工具、执行一次、run 结束即消失；恶意包与越权声明全部 fail-closed。

## 9. 发布节奏与测试门禁

### 9.1 节奏

- 每个版本一条 release lane：**特性冻结 → 门禁 → 真机验收 → 版本号与 CHANGELOG → 签名构建 → 打标签**。
- 补丁版本（`x.y.Z`）只修 P0 / P1，不夹带新功能。
- 每两个版本做一次完整真机回归（导航 / IME / 恢复 / 权限 / 分享 / 文件 / 网络）。
- `pubspec.yaml` 的 build number 单调递增（`versionCode` 由 pubspec 推导，不允许回退），`lib/constants.dart` 与 `CHANGELOG.md` 顶部版本必须一致。

### 9.2 门禁清单（每个版本必须全绿）

| 门禁 | 命令 / 检查 | 通过标准 |
| --- | --- | --- |
| 静态检查 | `cd flutter_app && flutter analyze` | 0 issue |
| Flutter 测试 | `cd flutter_app && flutter test --no-pub` | 0 失败 |
| Kotlin 单测 | `cd flutter_app/android && ./gradlew :app:testDebugUnitTest` | 0 失败 |
| 技能证据 | `cd flutter_app && dart run tool/skill_evals/run_skill_evals.dart` | `status=PASS`，`runtime-evidence.json` 与最终源码摘要一致 |
| 版本一致性 | `pubspec.yaml` / `lib/constants.dart` / `CHANGELOG.md` | 三者版本一致，build number 递增 |
| 工作树卫生 | `git status` 与忽略规则 | 构建中间产物（`.cxx/`、`build/`、`.dart_tool/`、本地签名文件）不入库 |
| 真机验收 | 见各版本「退出条件」 | 至少两台真机；弱网 / 切网场景纳入 v2.19 验收；未跑项标注 NOT RUN |
| 隐私回归 | 通知锁屏、备份内容、权限弹窗 | 无隐私内容、无明文凭据、权限按需 |

### 9.3 发布说明要求

- 每个版本在 `CHANGELOG.md` 写清：新增能力、行为变化、**遗留项**与未验证项。
- 已知缺陷按 P0 / P1 / P2 列出，P0 未清零不得发布。

## 10. 风险与待决策

| 风险 / 问题 | 影响 | 处理方式 |
| --- | --- | --- |
| 真机资源不足（型号 / 系统版本覆盖有限） | 权限与前台服务行为无法充分验证 | 每个版本固定至少两台真机；未跑项显式记录 |
| Provider 差异大（格式 / 限流 / 错误码） | 流式与错误文案不一致 | 统一错误分类与协议适配测试矩阵（v2.19） |
| 移动网络抖动与切网 | 流式中断、用户以为丢内容 | 保留部分文本 + 明确重试语义 + 弱网真机矩阵（v2.19） |
| MCP / 技能生态的信任边界复杂 | v2.20 可能引入新放行路径 | 清单为唯一能力来源；能力变宽必须重新同意 |
| 上游 Flutter / 插件升级 | 导航、IME、文件 API 行为漂移 | 升级单独成提交并跑全部门禁与真机矩阵 |
| 侧载分发的更新路径 | 用户升级失败或版本回退 | 保持签名校验与版本号单调递增，回退只在明确提示下允许 |
| 客户端只发往用户 Provider 的前提被误读 | 可能被误解为需要自建中转 | 文档与 UI 明确：无 ClawChat 中转、无账号、无遥测 |
